# Evaluation protocol

실제 상담 질문으로 두 가지를 확인한다.

1. 같은 모델에 vault의 근거를 제공하면 답변 품질이 나아지는가.
2. vault를 쓰는 챗봇이 고용노동부 AI 노동법 상담보다 나은 답을 주는가.

질문은 1350 공개 상담에서 모았다. 자료와 그 설명은 이용 조건 때문에 Git에서 제외한 `docs/evaluation/1350/`에 둔다.

## Dataset

- 질문은 실제 상담에서 관측한 것으로 두고, 1350 상담사 답변은 정답으로 쓰지 않는다.
- 관측한 사실과 분류 같은 판단을 다른 파일에 두고, 판단에는 누가 내렸는지 적는다.
- 원문은 공개 페이지를 내려받아 보관한다. 링크가 사라져도 대조할 수 있어야 한다.
- 사례에서 모델에 제공하는 입력은 비식별 재서술한 질문과 상담 기준일이다. 주제 분류와 게시 답변은 입력에서 제외한다.

## Dataset splits

development set(`dev`)은 오류를 분석하고 vault와 챗봇을 개선하는 데 쓴다. test set(`test`)은 개선을 마친 시스템을 평가하는 데 쓴다. 중복·후속 질문은 원래 상담과 묶고, 묶음의 조문이나 장·절을 기준으로 층화해 배정한다. 배정은 고정한다. 분할 전에 이미 개선에 활용한 사례는 독립 평가 점수에서 제외한다.

## Case selection

development set에서 같은 모델이 vault 유무에 따라 결론, 적용 조건, 필요한 사실 또는 다음 행동을 다르게 안내한 사례를 우선 검토한다. 두 답의 정오는 기준 답안으로 각각 확인한다. 두 답이 일치한 사례도 외부 서비스와 비교할 수 있도록 보관한다.

주 점수의 대상은 이직한 근로자의 급여 상담이다. 사업주의 신고·서류 제출 의무도 구직자가 자신의 권리와 절차를 확인하는 데 필요한 범위에서 다룬다. 현재 채점 범위는 질문에 붙인 고용보험법 장·절로 분류하므로, 사업주가 자기 업무를 묻는 사례까지 자동으로 구별하지는 못한다. 주 점수를 낼 때 질문의 관점도 확인한다. 자영업자·예술인·노무제공자 특례와 범위 밖 질문은 따로 집계하고 중복·후속 질문은 단독으로 채점하지 않는다.

## Model roles

| 역할 | 입력과 판정 |
| --- | --- |
| 사례 분류 | 질문과 법령 목차를 보고 관련 조문·장·절을 표시한다. 분류에 쓴 모델과 분류자별 결과를 보관한다 |
| 응답 생성 | 모델별로 질문·기준일·모델 설정을 고정하고 vault 근거를 제공한 응답과 제공하지 않은 응답을 짝짓는다 |
| 응답 비교 | 어느 조건의 답인지 가리고 결론이나 안내가 달라졌는지 판정한다. 두 응답 원문과 판정을 따로 보관한다 |
| 정확성 채점 | 양쪽 답을 각각 사람이 검토한 기준 답안과 대조한다 |

GPT와 Claude에서 vault의 효과를 비교할 때는 각 모델 안에서 얻은 차이를 보고한다. 현재 비교 도구는 vault 검색 단계에서 정한 조문 조회 기준일을 양쪽 응답 생성에 함께 전달한다. 같은 조회일에서 근거를 인용하는 답변 방식과 모델 자체 지식으로 답하는 방식의 차이를 측정한다.

2026-11 수집본의 장·절 분류는 같은 Claude 모델로 두 번 독립 수행했다. 분할 전에 수집한 응답 쌍 355건은 같은 GPT 모델로 생성했다. 이 기록은 개발 사례를 선별하는 데 쓴다. 분할 후 test set의 독립 평가 결과는 별도로 산출한다.

## Procedure

1. 같은 모델로 vault를 쓸 때와 쓰지 않을 때의 답을 받는다. 조건을 가린 두 답의 원문을 대조해 결론, 적용 조건, 필요한 사실이나 다음 행동이 달라지는 문항을 고른다. 선별 결과를 정오 판정과 따로 기록한다.
2. 우선 검토할 사례마다 기준 답안을 정한다.
3. 기준 답안과 어긋난 답마다 공식 원문, wiki 서술, 모델에 넘긴 근거, 답을 차례로 대조해 처음 어긋난 곳을 고친다. 고친 뒤 같은 질문과, 조건 하나만 바꾼 질문으로 전후를 비교한다.
4. 질문을 입력 문장으로 정제한다. 원래 질문의 사실을 더하거나 빼지 않는다.
5. 같은 입력을 AI 노동법 상담과 챗봇에 넣는다. AI 노동법 상담에는 직접 입력하고 첫 응답을 그대로 저장한다. 자동화하지 않는다.
6. 응답의 출처를 가리고 기준 답안으로 채점한다.

development set에서 여러 사례에 적용할 수 있는 지식 요구를 찾으면 [역량 질문](competency-questions.md)에 반영한다. 원래 상담 질문과 응답은 평가 자료에 둔다.

## Reference answers

- 이직일, 신청일 등 해당 규정의 적용 기준을 확인하고, 그 시점에 적용되는 법령과 행정규칙을 판례·법령해석례·고용24 공식 안내 등과 교차 확인한다.
- 1350 게시 답변을 대조 자료로 쓸 때는 작성 주체를 확인한다. 공개 페이지에 표시된 기관이나 부서는 출처로 기록한다.
- 결론, 결론이 달라지는 조건, 필요한 되물음, 근거 조문과 그 시행일을 적는다.
- 사람이 검토한 기준 답안만 채점에 쓴다.

## Scoring criteria

| 기준 | 확인할 것 |
| --- | --- |
| 정확성 | 자격, 금액, 기한, 신청 경로처럼 상담자의 행동을 바꾸는 쟁점이 기준 답안과 맞는가 |
| 참조 | 필요한 근거를 찾았는가, 쓰지 않을 근거를 끌어오지 않았는가 |
| 오염 | 질문에 없는 사실, 다른 시점의 규정, 근거 밖의 내용이 답에 섞이지 않았는가 |
| 간결성 | 상담자가 이해할 수 있는가, 불필요하거나 중복된 내용이 없는가 |

- 결론에 필요한 사실이 질문에 없으면 되물음도 맞는 응답으로 본다.
- 같은 사례의 여러 표현은 한 건으로 센다.
- 문항, 기준 답안, 제품 버전은 결과를 보기 전에 정한다.
- 개발에 쓴 문항의 결과는 그 문항에 한해 보고한다.

## Commands

질문 파일은 UTF-8 JSONL이며 각 행에 `id`, `as_of`, `question`이 있다.

```sh
uv run python -X utf8 scripts/bench_qa.py preview docs/evaluation/1350/questions.jsonl docs/evaluation/trial-01 --context historical --ids case-1
uv run python -X utf8 scripts/bench_qa.py freeze docs/evaluation/trial-01 docs/evaluation/fixed.json --ids case-1
uv run python -X utf8 scripts/bench_qa.py message docs/evaluation/fixed.json case-1
uv run python -X utf8 scripts/bench_qa.py blind docs/evaluation/fixed.json docs/evaluation/responses.jsonl docs/evaluation/grading-01
```

- `preview`: 두 조건의 첫 응답과 입력, 상담일, 모델 설정, 코드와 wiki의 식별 정보를 저장한다. vault를 사용한 응답에는 검색한 노트와 근거도 저장한다. `--context historical`은 과거 상담일 안내를 질문에 붙이고, `live`는 붙이지 않는다.
- `freeze`: 검토를 마친 문항의 입력과 응답을 고정한다.
- `message`: AI 노동법 상담에 붙여 넣을 문장을 출력한다.
- `blind`: 외부 응답(`responses.jsonl`의 `id`, `sent`, `first_response`)과 챗봇 답을 A/B로 섞어 `answers.json`에, 배정표를 `key.json`에 따로 쓴다.
