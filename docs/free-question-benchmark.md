# 자유질문 평가 절차

실제 상담 질문으로 두 가지를 확인한다.

1. 볼트가 같은 모델의 답을 바꾸는가.
2. 볼트를 쓰는 챗봇이 고용노동부 AI 노동법 상담보다 나은 답을 주는가.

질문은 1350 공개 상담에서 모았다. 자료와 그 설명은 이용 조건 때문에 Git에서 제외한 `docs/evaluation/1350/`에 둔다.

## 자료

- 질문은 실제 상담에서 관측한 것으로 두고, 1350 상담사 답변은 정답으로 쓰지 않는다.
- 관측한 사실과 분류 같은 판단을 다른 파일에 두고, 판단에는 누가 내렸는지 적는다.
- 원문은 공개 페이지를 내려받아 보관한다. 링크가 사라져도 대조할 수 있어야 한다.
- 모델에는 질문과 상담 기준일만 준다.

## 분할

사례를 개발용과 평가용으로 한 번 나누고 바꾸지 않는다. 수집 순서나 주제로 나누지 않고, 같은 조문을 묻는 서로 다른 사례가 양쪽에 고르게 들어가도록 조문별로 나눈다. 그래야 볼트가 고친 문항만 맞히는지, 처음 보는 사례에도 맞게 답하는지 가릴 수 있다. 같은 질문의 중복과 후속은 원래 질문과 같은 쪽에 둔다.

## 문항

| 구분 | 정의 | 쓰임 |
| --- | --- | --- |
| 핵심 문항 | 개발용 중 같은 모델의 답이 볼트 유무에 따라 결론, 조건 또는 행동에서 갈린 문항 | 볼트와 챗봇 개선, 외부 비교 |
| 비핵심 문항 | 개발용 중 볼트 유무로 답이 갈리지 않은 문항 | 외부 비교용으로 보관 |
| 평가용 문항 | 개발에 쓰지 않는 문항 | 성능 주장 |

점수는 질문이 묻는 고용보험법의 장·절에 따라 나눠 낸다. 이직한 근로자의 급여에 관한 질문이 주 점수다. 자영업자, 예술인, 노무제공자 특례와 범위 밖 질문은 따로 집계해, 모르는 것을 아는 척하지 않는지 본다. 중복과 후속은 단독으로 채점하지 않는다.

개발용 전체의 실행 결과로 볼트나 챗봇을 고치지 않는다. 고친 문항에서만 점수가 오르는 과적합을 막기 위해서다. 고치는 대상은 핵심 문항이다. 평가용 문항의 결과는 개선 방향을 정하는 데 쓰지 않는다.

## 순서

1. 같은 모델로 볼트 유무 양쪽 답을 받아 핵심 문항을 고른다. 모델의 자동 판정이 아니라 두 답의 원문을 대조한다.
2. 핵심 문항마다 기준 답안을 정한다.
3. 기준 답안과 어긋난 답마다 공식 원문, 위키 서술, 모델에 넘긴 근거, 답을 차례로 대조해 처음 어긋난 곳을 고친다. 고친 뒤 같은 질문과, 조건 하나만 바꾼 질문으로 전후를 비교한다.
4. 질문을 입력 문장으로 정제한다. 원래 질문의 사실을 더하거나 빼지 않는다.
5. 같은 입력을 AI 노동법 상담과 챗봇에 넣는다. AI 노동법 상담에는 직접 입력하고 첫 응답을 그대로 저장한다. 자동화하지 않는다.
6. 응답의 출처를 가리고 기준 답안으로 채점한다.

## 기준 답안

- 상담일에 시행 중인 법령, 행정규칙, 판례, 법령해석례와 고용24 공식 안내로 교차 확인한다.
- 1350 게시 답변은 상담사가 쓴 답변인지 확인한 뒤 대조 자료로만 쓴다.
- 결론, 결론이 달라지는 조건, 필요한 되물음, 근거 조문과 그 시행일을 적는다.
- 사람이 검토한 기준 답안만 채점에 쓴다.

## 채점

| 기준 | 확인할 것 |
| --- | --- |
| 정확성 | 자격, 금액, 기한, 신청 경로처럼 상담자의 행동을 바꾸는 쟁점이 기준 답안과 맞는가 |
| 참조 | 필요한 근거를 찾았는가, 쓰지 않을 근거를 끌어오지 않았는가 |
| 오염 | 질문에 없는 사실, 다른 시점의 규정, 근거 밖의 내용이 답에 섞이지 않았는가 |
| 간결성 | 상담자가 이해할 수 있는가, 불필요하거나 중복된 내용이 없는가 |

- 결론에 필요한 사실이 질문에 없으면 되물음도 맞는 응답으로 본다.
- 같은 사례의 여러 표현은 한 건으로 센다.
- 문항, 기준 답안, 제품 버전은 결과를 보기 전에 정한다.
- 개발에 쓴 문항의 결과는 그 문항에 한해 보고한다.

## 실행

질문 파일은 UTF-8 JSONL이며 각 행에 `id`, `as_of`, `question`이 있다.

```sh
uv run python -X utf8 scripts/bench_qa.py preview docs/evaluation/1350/questions.jsonl docs/evaluation/trial-01 --context historical --ids case-1
uv run python -X utf8 scripts/bench_qa.py freeze docs/evaluation/trial-01 docs/evaluation/fixed.json --ids case-1
uv run python -X utf8 scripts/bench_qa.py message docs/evaluation/fixed.json case-1
uv run python -X utf8 scripts/bench_qa.py blind docs/evaluation/fixed.json docs/evaluation/responses.jsonl docs/evaluation/grading-01
```

- `preview`: 볼트 유무 양쪽의 첫 응답을 입력, 상담일, 모델 설정, 코드와 위키의 지문과 함께 저장한다. 볼트 쪽은 검색한 노트와 근거도 저장한다. `--context historical`은 과거 상담일 안내를 질문에 붙이고, `live`는 붙이지 않는다.
- `freeze`: 검토를 마친 문항의 입력과 응답을 고정한다.
- `message`: AI 노동법 상담에 붙여 넣을 문장을 출력한다.
- `blind`: 외부 응답(`responses.jsonl`의 `id`, `sent`, `first_response`)과 챗봇 답을 A/B로 섞어 `answers.json`에, 배정표를 `key.json`에 따로 쓴다.
